## Template: Plain XeLaTeX Resume (Spectral Font)

The CV is a plain `article`-class XeLaTeX document (not moderncv) using the Spectral font via `fontspec`. Custom macros (`\resumesection{}`, `\entry{}{}{}`) reproduce a compact single-column resume layout.

**Base resume (canonical source):** `cv/travis_resume.tex` — this is the most up-to-date, general-purpose version of Travis's resume. Always start here when building a targeted variant, not from an older company variant.
**Company variant output file:** `cv/<company>/<role-slug>/travis_resume_<company>_<role-slug>.tex` (e.g. `cv/lockheed/mfc_embedded_intern/travis_resume_lockheed_mfc_embedded_intern.tex`) — one subfolder per company, and within it one subfolder per distinct application/role at that company (a company may get more than one application over time). Copy the current base resume into the new nested subfolder, then tailor.
**Compile with:** **xelatex** (the document requires `fontspec` to load the bundled Spectral `.ttf` files — `pdflatex` cannot load them).
**Page target: 1 page** — Travis is applying to US internships where 1 page is the universal standard. Do not target 2 pages. Cut content to fit rather than letting it run long.

**Never hand-edit `cv/web_resume.tex`/`.pdf`.** They are auto-generated by CI from `travis_resume.tex` (email/phone stripped) and published to travismbrown.com; they get overwritten on the next push regardless of local edits. See `cv/README.md`.

### Compile commands

Base resume, from `cv/`:
```bash
cd cv && xelatex -interaction=nonstopmode travis_resume.tex
```

Company variant, from inside its role-slug subfolder (the `-jobname` keeps the uploaded filename generic):
```bash
cd cv/<company>/<role-slug> && xelatex -interaction=nonstopmode -jobname="Travis_Brown_Resume" travis_resume_<company>_<role-slug>.tex
```

Expected output: `Output written on <jobname>.pdf (1 page).` Any page count other than 1 is a failure that must be fixed before presenting to the user.

## Document Structure

```latex
\documentclass[10pt]{article}

\usepackage[margin=0.35in, top=0.35in, bottom=0.35in]{geometry}
\usepackage{enumitem}
\usepackage[hidelinks]{hyperref}
\usepackage{parskip}
\usepackage{array}
\usepackage{fontspec}

\setmainfont{Spectral}[
  Path = fonts/,               % "../../fonts/" from inside a company/role-slug subfolder
  UprightFont    = Spectral-Regular.ttf,
  BoldFont       = Spectral-Bold.ttf,
  ItalicFont     = Spectral-Italic.ttf,
  BoldItalicFont = Spectral-BoldItalic.ttf
]

\setlength{\parindent}{0pt}
\setlength{\parskip}{0pt}
\raggedright

\setlist[itemize]{leftmargin=*, topsep=2pt, itemsep=2pt, parsep=0pt}
\let\olditemize\itemize
\renewcommand\itemize{\olditemize\fontsize{9.5}{12}\selectfont}

\pagestyle{empty}

\newcommand{\resumesection}[1]{%
  \vspace{5pt}%
  \noindent\textbf{#1}\\[-8pt]%
  \noindent\rule{\linewidth}{0.5pt}%
  \vspace{1pt}%
}

% #1 = Role/Project title  #2 = Company/Org  #3 = Date
\newcommand{\entry}[3]{%
  \noindent\textbf{#1}\\%
  \noindent\textbf{#2}\hfill#3%
}

\begin{document}

% HEADER: name, then contact line (email/phone wrapped in
% WEB-RESUME:REMOVE-START/END markers so CI can strip them for the public copy)

\resumesection{OBJECTIVE}
% One bold sentence, tailored per role

\resumesection{EDUCATION}
% Institution + degree line + GPA

\resumesection{SKILLS}
% 3 lines: Languages / Embedded / Tools

\resumesection{EXPERIENCE}
% \entry{...}{...}{...} + itemize bullets, most recent first

\resumesection{PROJECTS}
% \entry{...}{...}{...} + itemize bullets

\vfill
\end{document}
```

Section order is fixed by this structure (Objective → Education → Skills → Work Experience → Projects) — tailoring happens through content and emphasis within each section, not by reordering sections (unlike a moderncv-style template).

### Spacing inside itemize lists (important)

**Do not place `\vspace{...}` between `\item` entries in an `itemize` list.** Even though the source looks symmetric, this pattern occasionally produces a noticeably oversized gap before a single item: the inter-item `\vspace` creates a paragraph break that interacts unpredictably with the list's internal `\itemsep`, so LaTeX renders one of the gaps wider than the rest. Remove the inter-item `\vspace` and let `itemize` use its native uniform spacing.

```latex
% WRONG - intermittently produces an oversized gap before one bullet
\begin{itemize}
\item \textbf{Foo}: ...
\vspace{1pt}
\item \textbf{Bar}: ...
\end{itemize}

% RIGHT - uniform spacing using the list's native itemsep
\begin{itemize}
\item \textbf{Foo}: ...
\item \textbf{Bar}: ...
\end{itemize}
```

`\vspace{3pt}` between top-level `\entry{}{}{}` blocks within Work Experience or Projects is fine and should be kept — it gives breathing room between roles/projects and renders consistently.

## Section-by-Section Tailoring

### Objective (Best Practice)
This is the one-sentence bold statement right after the header, under `\resumesection{OBJECTIVE}`. It is the most important line to customize per role — it is the only place in this template that reads as a direct pitch rather than a bullet.

Keep it to a single sentence. State the target term/season and the specific domain, not a generic "seeking an internship" line. Examples already in use across variants:
- Base (broad): "Seeking an embedded/firmware engineering internship for Summer 2027."
- Lockheed: "Seeking a Summer 2027 embedded software internship focused on C/C++ firmware, RTOS, and drivers for defense systems."
- Blue Origin: "Seeking a Summer 2027 avionics software internship focused on C/C++ firmware, RTOS, and real-time flight systems."
- BAE Systems: "Seeking a Summer 2027 embedded software internship focused on C++ firmware and hardware testing for defense systems."

### Skills Section
Three lines, each a bolded category label followed by a comma-separated list: `Languages:`, `Embedded:`, `Tools:`. Reorder or lightly re-emphasize terms within each line to match the posting's vocabulary, but keep the three-category structure — do not add a fourth category or expand into a bulleted "Core Competencies" block; there is no room for it on a 1-page resume with this layout.

### Education
- Single entry: Rochester Institute of Technology, MS + BS in Computer Science (concurrent), GPA 3.96, expected December 2027.
- List Master of Science before Bachelor of Science (per Travis's preference — the MS is the terminal/primary degree even though both are earned concurrently).
- Do not add "(Accelerated BS/MS Program)" or similar parenthetical — Travis prefers this omitted from the resume line.

### Work Experience
- Each role is one `\entry{Title}{Company}{Dates}` block followed by an `itemize` of bullets, most recent role first.
- 3-4 bullets for GE Vernova (current/most relevant), 2-3 bullets for Lockheed Martin and RIT Electric Vehicle Team.
- Rewrite bullet content to emphasize aspects most relevant to the target role; keep concrete numbers and named tools/protocols intact.

### Projects
- Same `\entry{}{}{}` + itemize pattern as Work Experience.
- Currently: Autonomous Fixed-Wing Flight Controller, Handheld Chip-8 Emulator. Pick whichever 2 projects are most relevant to the posting; drop to 1 project only under genuine space pressure (see Page Budget below).

### Publications, Awards, References
Travis currently has none of the first two, and references are omitted per the Page Budget below ("available upon request" wastes space on a 1-page US internship resume). If this changes, add a short `\resumesection{}` block following the same pattern — do not add a References section back onto the resume even if asked informally; confirm with Travis first, since the page budget has no room for it.

## Compile-and-Inspect Loop (MANDATORY)

After writing the CV and before presenting to the user, always compile and visually inspect the PDF. Iterate until the layout is clean. Workflow:

1. Run `xelatex -interaction=nonstopmode travis_resume_<company>_<role-slug>.tex` from inside its role-slug subfolder (or the base-resume command from `cv/`)
2. Check the output page count: must be exactly 1
3. Read the PDF via the Read tool and visually inspect the page
4. Check that content fills the page well — a CV that ends well short of the bottom looks incomplete; restore a cut item if there's room. The `\vfill` before `\end{document}` pads any leftover space at the bottom, so a short document will show visible whitespace rather than silently compressing — treat that whitespace as a signal to add content back, not as acceptable padding.

### Fixing common page-break problems

This template has no moderncv-style automatic widow/orphan control, but the generic LaTeX rescues still apply:

**Problem: entry title on page 1, bullets orphaned to page 2**
Add `\usepackage{needspace}` to the preamble, then `\needspace{5\baselineskip}` immediately before the problematic `\entry{}{}{}` block:
```latex
\needspace{5\baselineskip}
\entry{Role Title}{Organization}{YEAR--YEAR}
\begin{itemize}
...
\end{itemize}
```

**Problem: content spills just barely onto a second page**
Add `\enlargethispage{2-3\baselineskip}` right before `\end{document}` (or before the last section that's spilling) to stretch page 1 by a few lines. This is the standard LaTeX rescue for near-miss overflows — use it before resorting to content cuts.

**Problem: 2 pages with substantial content on page 2**
Cut content — do not shrink the geometry margins, `\fontsize`, or `\itemsep` to force-fit. See "Relevance-weighted cutting" below for the rule.

**Problem: content finishes early, page 1 has a large empty gap from `\vfill`**
Restore the highest-relevance item that was previously cut — a 1-page resume with a big empty bottom margin looks incomplete, not clean.

## ATS Parseability

Most employers run CVs through an ATS before a human sees them, and the ATS reads the PDF's embedded **text layer**, not the rendered page. This template is a plain single-column layout with no icon fonts (no fontawesome contact icons — email/phone/links are printed as literal text with `\href`), so it is inherently low-risk for ATS parsing compared to icon-heavy templates. Still verify after every content change:

```bash
cd cv/<company>/<role-slug> && pdftotext -layout Travis_Brown_Resume.pdf Travis_Brown_Resume.txt
```

`pdftotext` comes from [poppler](https://poppler.freedesktop.org/), not the TeX distribution — it is an **optional** dependency. If it is not installed, skip the mechanical check with a warning and rely on the visual PDF read for keyword coverage.

What to check in the extraction:

- **Contact details as literal text.** Email, phone, GitHub, website, and LinkedIn are all set with `\href{...}{visible text}` — the visible text should extract cleanly since there are no icon glyphs involved. Confirm the email and phone number both appear verbatim in the extracted text.
- **No garbled output.** `(cid:NNN)` markers or `�` characters mean the Spectral font's Unicode mapping broke on this system's XeLaTeX/fontconfig setup — flag this immediately, it should not happen with the bundled `.ttf` files.
- **Reading order.** Single-column layout, so extraction order should always match visual order. If it doesn't, something is wrong with the compile, not the template design.
- **Keyword coverage.** Match the posting's required/preferred terms against the extracted text. Prefer the posting's exact term over a synonym when it is truthfully applicable — ATS matching is often literal. Never add a keyword the profile does not support.

## Page Budget - Hard 1-Page Limit

Travis is applying to US internships. The CV **must** fit on exactly 1 page when compiled. Use these content limits as a guide:

| Section | Max budget |
|---------|-----------|
| Objective | 1 sentence |
| Education | 1 entry (RIT MS + BS + GPA) |
| Skills | 3 lines (Languages / Embedded / Tools) |
| Most recent role (GE Vernova) | 3-4 bullets |
| Other roles (Lockheed, RIT EVT) | 2-4 bullets each |
| Projects | 2 projects, 2-3 bullets each |
| References | Omit — "available upon request" wastes space on a 1-page US resume |

**If in doubt, cut rather than squeeze.** Reducing `\itemsep`, font size, or geometry margins to force-fit content makes the resume look cramped. Cut the lowest-relevance content first.

## Relevance-weighted cutting (the right way to shrink a CV)

**Cut by signal, not by section.** Static priority lists ("remove oldest education first, then shorten the earliest role...") are wrong when a relevant "lower-priority" item is competing with an irrelevant "higher-priority" item. An older-role bullet that speaks directly to the posting is worth more than a recent-role bullet that does not.

For every candidate line, score three things:

1. **Relevance to THIS posting** — does the line hit a named tool, keyword, or stated responsibility in the job ad?
2. **Uniqueness** — is it the only place this claim appears, or is it duplicated elsewhere in the CV?
3. **Narrative load** — does the cover letter depend on it? If cutting the line would force you to rewrite a cover-letter paragraph, it is load-bearing.

Cut the lowest-total-score line first, regardless of which section it sits in.

### Practical order of cuts (easiest → last resort)

1. **Low-relevance experience bullets.** A bullet about work that does not touch posting keywords, wherever it sits.
2. **Lowest-relevance project.** Drop from 2 projects to 1 if space is genuinely tight.
3. **Low-relevance supporting content within a bullet.** A clause or example inside a bullet that doesn't touch posting keywords, trimmed rather than the whole bullet cut, if that's enough to reclaim the needed line.
4. **Last-resort structural cuts.** Tightening an older role (RIT EVT or Lockheed) to 2 bullets. These only happen if the relevance-weighted cuts above have already been exhausted.

### Pitfalls to avoid

- Do not mechanically cut from the bottom of a static section list without checking relevance. "Cut the oldest role first" is wrong if that role is literally about the skill the posting asks for.
- Do not cut the one concrete example the cover letter leans on. Relevance is measured against the cover letter you wrote, not just the job posting — interviewers will have read both.
- Do not cut to fit if the fit is borderline. Prefer `\enlargethispage{2-3\baselineskip}` for near-misses; reserve content cuts for genuine overflow onto a real second page.
